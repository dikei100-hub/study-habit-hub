## 1. 하루 경계 (가장 중요)

- 하루는 자정이 아니라 **새벽 4시**에 바뀐다.
- `04:00 ~ 다음날 03:59` 는 **같은 날**로 친다.
- 이유: 밤 12시를 넘겨 공부한 것을 전날 기록으로 잡기 위함. 야간 사용자 배려.
- 계산은 **`src/lib/studyDay.ts` 의 `getStudyDate()` 한 곳에서만** 한다.
  - 다른 파일에서 `new Date().toISOString().slice(0,10)` 같은 직접 계산 금지.
  - 규칙이 바뀔 때 한 파일만 고치면 되도록 유지한다.

## 2. 리스트 관리 체크박스의 의미 ★

체크박스는 **"그 날짜의 할 일 목록에 이 항목이 들어 있는가"** 를 그대로 비추는
파생값이다. 따로 저장되는 on/off 상태가 아니다.

- 끄면 → 그 날짜에서만 빠진다. 다음 날은 다시 깔린다.
- 켜면 → 그 날짜 목록에 미완료로, 템플릿 순서상 제자리에 다시 들어간다.
체크는 이제 **그 날짜에 담는 유일한 수단**이다. 체크하지 않으면 그날 목록에 없다.

- 오늘의 할 일 **완료 체크와는 무관하다.** 완료해도 목록에는 남으므로 체크는
  켜진 채다.
- 목록에서 영구히 빼려면 휴지통.

## 3. 리스트 관리 시트

- 오늘 화면과 캘린더 화면의 "리스트 관리" 버튼으로 연다.
- 화면 전환이 아니라 **아래에서 올라오는 시트(bottom sheet)**.
- **대상 날짜**: 오늘 화면에서 열면 오늘, 캘린더에서 열면 선택된 날짜.

### 동작

- **추가**: 새 항목은 **목록 맨 위**에 넣는다. 맨 아래 아님.
  (목록이 길어지면 아래는 찾기 어렵기 때문)
  새 항목은 대상 날짜의 할 일에 즉시 나타난다.
  빈 문자열·공백만 입력은 추가하지 않는다.
- **체크박스**: 2장 참고 (그 날짜 목록에 들어 있는가).
- **휴지통**: 목록에서 **완전 제거**. 대상 날짜의 할 일에서도 함께 사라진다.

### 이 앱의 전제

매일 같은 일을 반복하는 사용자를 위한 앱이다.
그래서 이 목록이 기준이 되고, 매일 그대로 넘어간다.

---

## 4. 오늘의 할 일

- 각 항목에 **삭제 버튼**이 있다.
- 삭제하면 **그 날짜에서만** 빠진다.
- 리스트 관리 목록은 건드리지 않으므로 **다음 날 다시 나타난다.**
  (예: "오늘은 학원 가서 못 하니까 빼자" → 내일은 다시 나옴)
- 오늘의 할 일의 삭제 버튼은 **2장의 체크 끄기와 같은 동작**이다.
  두 화면은 같은 것을 본다.

---

## 5. 담기 (자동으로 채우지 않는다)

**자동으로 채우지 않는다.** 어떤 날짜도 열었다고 해서 할 일이 생기지 않는다.
리스트 관리에서 **체크한 것만** 그 날짜 목록에 담긴다. 오늘도 같다.

그 날짜를 처음 건드리면 **빈 목록**이 만들어지고 거기에 담긴다.
앱을 열지 않은 날은 목록 자체가 없다.

미리 담아둘 수 있다. 일요일에 다음 주 7일치를 각각 담아두면 그날 그대로 나온다.

**왜 이렇게 정했나:** 템플릿이 모든 날에 자동으로 깔리던 때, 특정 날짜에만
넣으려던 할 일이 다른 모든 날에 나타났다. 자동 채우기를 없애니 그 문제가
원인에서 사라졌고, 별도 일회성 수단도 필요 없어졌다.

**감수하는 것:** 매일 그날 할 일을 담아야 한다(담을 때 한 번, 완료할 때 한 번
체크). 앱을 아예 안 여는 날은 **할 일 0개인 날**이 된다 — 예정 0개인 날은
완벽이 아니고 완료 0이면 공부한 날도 아니다(8장). 계산 규칙은 그대로 두고
이 변화만 받는다.

달력 표시는 다르다. 빈 목록인 날은 0% 링이 아니라 `-`(기록 없음)로 보이고
스트릭도 그날에서 끊긴다. "이 날짜를 건드린 적이 있나"(키 존재)와 "보여줄
기록이 있나"(화면 표시)는 다른 질문이므로 기준이 다르다.

## 6. 날짜별 편집 규칙

| 날짜 | 완료 체크 | 항목 추가/삭제 | 리스트 관리 버튼 |
|------|-----------|----------------|------------------|
| **과거** | 불가 | 불가 | 숨김 |
| **오늘** | 가능 | 가능 | 표시 |
| **미래** | 불가 | 가능 | 표시 |

- 과거 날짜는 **그날 무엇을 했고 무엇을 안 했는지 확인하는 용도**다.
- 미래는 미리 계획만. 완료는 그날이 되어야 한다.

### 화면도 그렇게 보여야 한다

완료 체크는 **오늘만** 가능하다는 규칙은 그대로다. 화면도 그렇게 보여야 한다 —
과거·미래 날짜에는 **체크박스를 그리지 않는다.** 눌러도 안 되는 컨트롤을 남기면
"고장인가" 로 읽힌다. 미래의 미완료 항목은 `예정`, 과거의 미완료 항목은
아무 표시도 하지 않는다. 미래에도 목록 구성(리스트 관리·삭제)은 가능하다.

- 누를 수 없는 자리는 `<button>` 으로도, 비활성 버튼으로도 만들지 않는다.
- 과거의 **완료된 항목은 체크 표시를 남긴다.** 무엇을 했는지가 기록이다.
- 미완료 자리는 **배경 없이 비운다.** 회색 네모를 남기면 그것 자체가 빈
  체크박스로 보여 고친 것이 없어진다. 자리는 그대로 차지해 줄 높이를 맞춘다.

## 7. 화면 구성

### 탭 (하단 고정, 4개)

```
오늘  /  통계  /  캘린더  /  보상
```

- 안드로이드판은 상단 탭이지만, **웹은 하단**이다. iOS 한 손 조작 고려.
- 선택된 탭은 연보라 배경의 둥근 사각형으로 강조. 아이콘 위, 글자 아래.
- **설정은 탭에 없다.** 각 화면 오른쪽 위 톱니 아이콘으로 진입.
- 톱니를 누르면 설정 시트가 열린다. 현재 항목은 **데이터 초기화** 하나뿐이다.
  홈 화면 웹앱은 콘솔을 쓸 수 없어 화면 안에 초기화 수단이 반드시 필요하다.

### iOS 대응

- `index.html` viewport 에 `viewport-fit=cover`
- 탭바에 `env(safe-area-inset-bottom)`, 본문 상단에 `env(safe-area-inset-top)`
- 본문 최대 폭 420px, 가운데 정렬. 모바일 전용.
- `public/manifest.webmanifest` + `apple-touch-icon`(180) +
  매니페스트 아이콘(192·512·maskable 512). 아이콘 원본은 안드로이드판의
  햄스터(졸업모자)이고, 연보라 `#E8DFF7` 배경에 맞춰 정사각형으로 만들었다.
- 홈 화면 추가 후에는 iOS 가 아이콘을 잘 갱신하지 않는다. 아이콘을 바꾸면
  홈 화면에서 지우고 다시 추가해야 한다.

### 내 컬렉션

보상 탭의 `내 컬렉션 모두 보기` 를 누르면 컬렉션 시트가 열린다.
보상 탭은 **획득한 것만** 보이고, 컬렉션에 트로피 3종과 배지 12종 전부가
조건과 함께 나온다. 미획득은 회색조로 흐리게 두되 숨기지 않는다 — 목표가
보여야 동기가 된다.

코인 잔액은 **컬렉션 헤더와 보상 탭의 컬렉션 진입 버튼 안** 두 곳에 같은 알약
모양으로 보인다.

> C-1 에서 "코인은 쓰는 곳 옆에" 라며 보상 탭의 코인 카드를 떼고 컬렉션 헤더로
> 옮겼는데, **써 보니 아니었다.** 성취를 확인하러 온 화면에 코인만 없는 것이
> 어색했다. 카드를 되살리는 대신 진입 버튼 안에 알약으로 넣어, 들어가서도
> 같은 모양이 이어지게 했다.

배지 조건 문구는 **사용자 말로 풀어쓴다.** 안드로이드는 `완벽한 날 50일` 처럼
내부 용어를 그대로 노출해 뜻이 안 통했다(`Lessons` 1-3). 웹은
`모두 완료한 날 50일` 로 쓴다. 문구는 `rewards.ts` 의 `BADGE_REQUIREMENTS`
한 곳에 둔다. 트로피 이름도 같은 이유로 `TROPHY_NAMES` 한 곳에서만 온다.

> `CrossTrack_AppSpec.md` 4-4 는 보상 탭 격자에 미획득까지 모두 나온다고
> 적었으나 **실제 앱과 다르다.** 그 문서에 정정 주석을 달아 뒀다.

### 배지 상세

보상 탭의 **획득한 배지를 누르면** 상세 시트가 열린다. 큰 그림·이름·조건과
함께 **획득일**을 보여준다. 획득일은 `earnedBadges` 에 저장돼 있지만 여기 말고는
화면 어디에도 나오지 않는다 — 조건은 컬렉션에도 있으므로, **획득일이 두 화면의
역할을 가른다.**

배지 원본은 192×192 인데 격자에서는 72px 로 보여 세밀한 부분이 묻힌다. 상세는
160px 로 키운다.

획득일이 없을 수도 있다(옛 payload·손상된 값). 그때는 대비 문구를 보이고 화면이
죽지 않게 한다. 날짜는 문자열을 직접 자르지 않고 `parseDateKey` 를 지난다(1장).

미획득 배지와 트로피는 상세가 없다. 필요해지면 그때 붙인다.

### 톤

- 카드 라운드 20px 내외, 아주 옅은 그림자, 테두리 없음.
- 글자 크게, 여백 넉넉하게, 정보 밀도 낮게.
- 문구는 **"관리"가 아니라 "응원"**. 지시형 대신 격려형.
- 앱 아이콘은 실제 이미지가 들어왔다 (위 "iOS 대응" 참고).
- **마스코트(햄스터)·배지 12종·트로피 3종이 모두 반영됐다.** `BadgeSlot`
  placeholder 는 사라졌다.
- ★ **배지 파일명은 옛 코드라 현재 조건과 다르다.** `badge_study_10` 이 누적
  100개, `_50` 이 300개, `_100` 이 500개다. 파일명 숫자로 짐작하지 말 것.
  매핑의 기준은 `CrossTrack_Assets.md` 2절이고, 코드에서는 `Screen.tsx` 의
  `badgeSrc` 한 곳에만 둔다.
- 미획득 배지는 숨기지 않고 회색조 + 낮은 불투명도로 흐리게 둔다.
  목표가 보여야 동기가 된다.
- 마스코트는 달성률 3단계로 바뀐다: 0% `hello` / 1~99% `good` / 100% `congrats`.
  통계 화면은 `graduate`, 보상 상단 칭찬 카드는 `congrats`,
  리스트 관리 시트는 `hello`. **`graduate` 는 통계 한 곳에만 쓴다.**
- 이미지는 256×256 투명 PNG. 안드로이드 원본에서 배경을 걷고 여백을 잘라
  크기를 맞춘 것이다(원본 합계 4.7MB → 280KB).
- 배지·트로피 이미지는 192×192 투명 PNG. 안드로이드 원본(nodpi) 그대로다.
- 화면이 파일 경로를 직접 쓰지 않는다. `Mascot` 의 `kind`, `Badge` 의 `code`,
  `Trophy` 의 `id` 로만 고른다.

## 8. 보상 규칙

이 앱에는 "하루의 성공" 기준이 **두 개** 있다. 섞지 말 것.

- **습관 축** — 그날 하나라도 완료했는가. 문턱이 낮다. 스트릭·누적 배지가 이 축.
- **완벽 축** — 그날 할 일을 다 했는가. 코인·완벽 계열 배지가 이 축.

안드로이드판은 초기에 스트릭과 큰 배지까지 전부 완벽 축에 묶었다가,
대부분 도달 불가능해져서 분리했다. 웹은 처음부터 분리한다.

### 코인

- **하루 100% 달성 시 +10코인.** 하루에 한 번만.
- 부분 달성(75% 등)에는 지급하지 않는다. 목표는 "완주".
- 이미 100% 달성해 받은 뒤 할 일을 추가했다가 다시 100%를 만들어도 추가 지급 없음.

스트릭은 완화했지만 코인은 여전히 **완벽 축(100%)** 이다. 이 비대칭은 의도된
것이다. 습관은 넉넉히 인정하고, 재화는 완주에만 준다.

### 스트릭 (연속 기록)

- **연속으로 "인정되는 날"이 이어진 수.**
  하루가 인정되는 조건: 그날 완료 개수 ≥ 1, **또는** 그날이 방어(프리즈)된 날.
  완료 개수는 그날 예정 개수와 무관하다.
  (프리즈는 웹 미구현. 붙일 때를 위해 조건을 미리 적어둔다.)
- **시작점 유예:** 오늘이 아직 조건을 못 채웠으면 오늘을 실패로 세지 않고
  어제부터 과거로 센다. 진행 중인 하루를 끊김으로 처리하지 않기 위함.
- **방향과 종료:** 시작일에서 과거로 하루씩 내려가며 센다.
  **기록이 아예 없는 날을 만나면 즉시 끊김.** 무한 방지 상한을 둔다.
- **최고 기록은 줄어들지 않는다.** 기존 최고값과 새 계산값 중 큰 값.
- 저장값이 아니라 **기록에서 매번 재계산**한다. 소급 수정에도 자동 정합.

> 완화한 이유: 66%만 해도 "끊겼다"고 뜨면 매일 공부한 사용자가 혼란스럽다.
> 습관 축은 문턱을 낮춘다.

**표시 문구는 `연속 공부` 다.** 전에 쓰던 `연속 달성` 은 "달성" 이 완벽 축(100%)을
암시해 뜻과 어긋났다 — 스트릭은 습관 축이다. `Lessons` 1-4 의 "단어의 함의를
조심하라" 에 해당하고, 안드로이드가 "꾸준히" 를 썼다가 '연속' 을 암시해 폐기한
것과 같은 종류다.

### 트로피 (상점형, 코인으로 구매)

| 트로피 | 가격 |
|--------|------|
| 브론즈 | 100코인 |
| 실버 | 300코인 |
| 골드 | 600코인 |

- 순서대로만 구매 가능. (브론즈 → 실버 → 골드)

**잔액을 빼지 않는다.** 잔액은 `지급 날짜 수 × 10 − 구매한 트로피 값의 합` 으로
파생되므로, 구매는 `purchasedTrophies` 에 하나 더하는 것이 전부다. 이중 차감이
구조적으로 불가능하다.

막아야 할 것은 **같은 트로피를 두 번 사는 것** 하나뿐이고, 리듀서가 실행
시점에 조건을 다시 검사해 막는다. 화면의 가드만 믿지 않는다(`Lessons` 3-7).
판정은 `canPurchase` 한 곳이고 화면이 보여주는 것과 **같은 판정**이다 — 두 곳에서
따로 계산하면 살 수 있다고 보여주는데 눌러도 안 되는 버튼이 생긴다.

첫 구매는 `b12`(첫 트로피) 배지를 함께 준다. 축하 팝업은 배지와 트로피를
**하나의 팝업**에서 함께 보여준다. 따로 띄우면 겹친다.

### 배지 (조건형, 행동으로만 획득)

| 배지 | 조건 | 축 |
|------|------|-----|
| 첫걸음 | 첫 완벽 달성 | 완벽 |
| 첫 연속 | 3일 연속 | 습관 |
| 열공 7일 | 공부한 날 누적 7일 | 습관(누적) |
| 열공 30일 | 공부한 날 누적 30일 | 습관(누적) |
| 열공 100일 | 공부한 날 누적 100일 | 습관(누적) |
| 완벽한 주 | 최근 7일 모두 기록 존재 && 모두 100% | 완벽 |
| 완벽 마스터 | 완벽한 날 50일 | 완벽 |
| 노력왕 | 누적 완료 100개 | 누적 |
| 성실왕 | 누적 완료 300개 | 누적 |
| 공부왕 | 누적 완료 500개 | 누적 |
| 공부의 신 | 하루 5개 이상 완료한 날 100일 | 누적 |
| 첫 트로피 | 트로피 첫 구매 | 상점 |

바뀐 점:

- `연속 30일`·`연속 100일` → **누적**으로. 리셋되는 연속은 큰 수에서 달성 불가라
  "영원히 못 받을 장식"이 된다.
- 누적 완료 개수 계열의 옛 이름 3종 → 계열이 "왕 / 광 / 마스터"로 뒤죽박죽이었고
  그중 하나는 독서 앱에서나 쓸 말이라 이 앱과 맞지 않았다.
  노력왕 → 성실왕 → 공부왕 → 공부의 신 으로 등급감을 통일.

### 판정 규칙

- **완벽한 날** = 전체 개수 > 0 **그리고** 완료 개수 == 전체 개수.
  ★ 예정된 할 일이 0개인 날은 완벽이 아니다. 공짜 완벽을 주지 않는다.
- **달성률** = 완료 ÷ 전체 × 100. 전체가 0이면 0%.
  통계·캘린더 어디서나 같은 공식을 쓴다.
- **정산 순서: 코인 → 스트릭 → 배지.** 배지가 마지막인 이유는 스트릭 정산이
  끝나야 최신 최고연속값으로 연속형 배지를 판정할 수 있기 때문.
- **획득한 배지는 취소하지 않는다.** 조건이 다시 거짓이 되어도 유지.
  미획득 배지도 잠금 상태로 목록에 모두 보인다.
- **내부 식별자와 표시 이름을 분리한다.** 이름·기준을 바꿔도 획득 데이터가
  안전하도록. 안드로이드는 식별자를 의미와 묶었다가 기준을 바꾸자 어긋났다.

### 배지 획득 축하

배지를 새로 받으면 **화면 가운데 축하 팝업**이 약 2.5초 뜬다. 어느 탭에 있든
뜬다. 앱을 열 때의 정산(소급 획득)에는 뜨지 않는다 — 이번 조작으로 새로 받은
것에만 뜬다. 안드로이드판은 획득 연출이 아예 없어 "성취의 순간이 없다" 가 가장
큰 아쉬움이었다(`RewardNotes` [3]·[6]).

- 무엇이 새것인지는 정산 전후 `earnedBadges` 의 **차집합**으로 안다.
- 대기 목록(`justEarned`)은 리듀서 상태에만 있고 **저장하지 않는다.**
- 트로피 구매 축하는 B-3 에서 붙인다.

### 스트릭 프리즈 — 웹판 미구현

안드로이드판에는 있으나 웹판에는 아직 없다. 붙일 때 규칙은 아래와 같고,
더 자세한 배경은 `RewardSystemDesign.md` 4장 참고.

- 대상은 항상 **어제 하루.** 오늘은 아직 만회 가능하므로 방어하지 않는다.
- 제안 조건(모두 충족): 어제가 인정 안 되는 날 && 어제 직전 연속 3일 이상
  && 코인 50 이상 보유.
- **적용 순서(반드시 이 순서):** ① 어제를 "방어됨"으로 표시(기록이 없으면
  만들어서라도) → ② 코인 50 차감(0 미만 불가) → ③ 스트릭 재계산.
  ①을 먼저 해야 ③이 그날을 이어짐으로 센다.
- 세 단계를 하나의 액션에서 처리하고 실행 직전 재검사한다(이중 차감 방지).
  웹은 리듀서가 단일 스레드라 한 액션 안이면 그 자체로 원자적이다.
- 방어한 날은 연속만 이어지고 코인은 지급되지 않는다.
- 붙일 때 **하루 인정 판정은 한 곳만 고치면 된다.** 스트릭 계산이 그 판정
  하나를 통해서만 날짜를 보도록 이미 모아 뒀다(`isStreakDay`).

### 통계 표시 규칙

- **이번 주 달성률**은 일~토 달력 주간을 잰다. 아직 지나지 않은 날은 기록이
  없으므로 분모에 들어가지 않는다.
- **증감**은 "이번 주 경과분 vs 지난주 같은 경과분" 을 비교한다.
  오늘이 수요일이면 양쪽 다 일~수 4일씩이다. 도넛과 증감이 같은 것을 재도록.
- 어느 한쪽이라도 기록이 없으면 증감을 표시하지 않는다.
- 표시 문구는 **상태에서 파생**시킨다. 화면이 직접 계산하면 서로 모순되는
  두 경로가 생긴다.

**최근 7일 막대그래프는 세 갈래다.**

| 그날 | 막대 |
|---|---|
| 기록 없음 (앱을 안 연 날) | 아무것도 그리지 않는다 |
| 0% 달성 (담았는데 못 함) | 바닥에 붙은 얇은 막대, 흐린 색 |
| 1% 이상 | 높이가 달성률인 막대 |

담았는데 하나도 못 한 날과 아예 안 연 날은 **다른 상태**다. 캘린더가 `0%` 와
`-` 로 가르므로 **두 화면이 같은 상태에 같게 답해야 한다.** 그러려면
`last7Days` 가 `rate` 만 담지 말고 `hasRecord` 도 실어야 한다.

## 9. 데이터 저장

- 저장소 접근은 **`src/lib/storage.ts` 를 통해서만** 한다.
  다른 파일에서 `localStorage` 직접 호출 금지.
- 현재 저장 키는 **`studymate.state.v2`** 다.
  2장 재정의(템플릿 `enabled` 제거)로 스키마가 바뀌면서 올렸다.
  마이그레이션은 두지 않았고, 옛 `v1` 키는 지우지 않고 그대로 남겨둔다.
- 현재는 브라우저 localStorage. **나중에 Supabase로 교체 예정**이므로
  이 파일 하나만 고치면 갈아탈 수 있는 구조를 유지한다.
- 값이 없거나 깨진 경우에도 앱이 죽지 않고 초기값으로 시작할 것.

### 보상 저장

아래 셋만 저장하고 나머지는 기록에서 재계산한다.

- `earnedBadges` — 획득한 배지 코드와 획득일
- `coinAwardedDates` — 코인을 지급한 날짜 목록
- `purchasedTrophies` — 구매한 트로피

코인 잔액은 저장하지 않는다. `지급 날짜 수 × 10 − 트로피 사용액` 으로 파생한다.
안드로이드는 코인 지급 여부를 날짜별 기록의 플래그로 뒀는데, 그러면 코인 로직이
일별 기록에 묶인다(`RewardNotes` [6] 2번). 웹은 날짜 목록을 따로 둔다.

**한 번 준 것은 뺏지 않는다.** 배지는 미획득→획득으로만 승격하고, 코인 지급
날짜는 목록에서 빠지지 않는다. 체크를 풀어도 배지와 코인은 남는다.

축하 대기 목록(`justEarned`)은 배지와 트로피를 함께 담고 **저장되지 않는다.**
표시 이름과 id 를 함께 담아 팝업이 이름으로 코드를 역추적하지 않게 한다.

내부 식별자는 `b01` 같은 **의미 중립 코드**다. 표시 이름은 별도 맵에서 관리해
이름·기준을 바꿔도 획득 데이터가 안전하게 한다.

정산은 **리듀서 안에서** 한다(`src/state/StudyStore.tsx`). 별도 이펙트로 빼면
이중 실행 위험이 생긴다. 판정 자체는 `src/lib/rewards.ts` 의 순수 함수다.

`saveState` 는 `todosByDate` · `templates` · `rewards` **세 필드만 명시적으로
골라** 직렬화한다. 리듀서는 화면용 임시 값(`justEarned`)도 함께 들고 있는데,
통째로 넘기면 그것까지 저장된다. 거르는 자리를 저장 경계에 두어 앞으로 임시
값이 늘어도 저장소가 오염되지 않게 했다.

### 데이터 보관과 개인정보

공개 배포이므로 **데이터가 브라우저에만 있다는 것**을 설정 시트에서 알린다.
기기를 바꾸거나 브라우저 데이터를 지우면 사라진다. 나중에 잃고 나서 알면 늦다.

이 앱은 **외부로 데이터를 보내지 않는다.** 분석 도구도 추적도 없고 로그인도
서버 저장도 없다. **수집하는 개인정보가 0 이다.** 고등학생 대상 앱에서 이것은
큰 장점이므로 **이 성질을 유지할 것** — 나중에 무엇을 붙이더라도 여기서부터
다시 판단한다.

### 첫 실행 상태

저장된 값이 없을 때 만들어지는 상태는 아래가 전부다.

- 리스트 관리 템플릿 3개 (**아무것도 체크되지 않은 상태**)
- **할 일 0개.** 오늘 것도 만들지 않는다 — 자동으로 채우지 않는다(5장).
- **과거 기록 0건.** 캘린더는 전부 `-`, 스트릭 0, 통계 0%

첫 화면은 빈 상태 안내가 뜬다. 리스트 관리에서 체크해야 오늘 목록에 담긴다.

**개발용 가짜 데이터:** `src/lib/devSeed.ts` 의 `DEV_SEED`. 통계·캘린더를
만들 때 켜서 쓴다. **항상 `false` 로 커밋한다.** 켠 채로 내보내면 실사용자에게
가짜 기록이 보인다.

## 11. 작업 원칙

- **데이터·상태 로직 변경은 단독 사이클.** UI 폴리싱과 섞지 말 것.
- UI 조정(색·문구·여백)은 묶어도 됨. 애매하면 나눈다.
- 판단 기준은 "**복구가 싼가**".
- **문서와 실제 화면이 다르면 화면이 정답이다.** 문서는 실제 앱보다 낡는다.
- 러버블과 로컬 양쪽에서 고치지 말 것. **수정은 로컬에서만.**
  (GitHub 양방향 동기화라 충돌 위험)

## 12. 환경

```
경로: D:\AI_PJT\11_Web_ios\study-habit-hub
저장소: github.com/dikei100-hub/study-habit-hub
스택: React + Vite + TypeScript + Tailwind
실행: npm run dev  →  http://localhost:8080
실기기 확인: 같은 와이파이에서 http://<PC IP>:8080
```

- `bun.lock` 이 커밋돼 있지만 **로컬에 bun 이 설치돼 있지 않아 npm 을 쓴다.**
  실행 명령은 `npm run dev` 로 통일한다. (`dev` 스크립트는 `vite dev` 라
  어느 쪽으로 돌려도 결과는 같다.)

- 차트 라이브러리 쓰지 않음. 막대·도넛은 div/CSS 또는 인라인 SVG로 직접 구현.
- 아이콘은 lucide-react 만 사용.

### 프로덕션 빌드

```
npm run build      →  .output/  (약 27초)
npx vite preview   →  빌드 결과 미리보기
```

산출물은 `.output/` 하나다.

```
.output/
├── nitro.json                preset·진입점 메타
├── public/                   정적 파일 (assets/ 는 1년 캐시 헤더가 붙는다)
└── server/
    ├── index.mjs             ★ 서버 진입점
    └── wrangler.json         Cloudflare 배포 설정 (자동 생성)
```

`.output` · `.wrangler/` · `dist` · `.nitro` 는 모두 `.gitignore` 에 있다.
**빌드 결과물은 커밋하지 않는다.**

### 배포 타깃

nitro 의 기본 preset 은 **`cloudflare-module`** 이고 `src/server.ts` 의
`export default { fetch(request, env, ctx) }` 도 Cloudflare Workers 서명이다.

**배포처는 Vercel 로 정했다.** Vercel 의 git 연동으로 빌드하면 nitro 가 빌드
환경을 자동 감지해 **코드를 고치지 않아도** Vercel 형식으로 나온다.
`NITRO_PRESET=vercel npm run build` 로 실제 확인했다 — preset `vercel`,
진입점 `.vercel/output/functions/__server.func/index.mjs`.

`vite.config.ts` 에 `nitro: { preset: "vercel" }` 로 하드 핀할 수도 있으나
git 연동만으로 충분하므로 두지 않는다.

> ★ **`.gitignore` 에 `.vercel/` 이 없다.** 배포 사이클의 **첫 커밋**으로
> 반드시 넣을 것. 없으면 빌드 산출물이 미추적으로 남아 실수로 커밋된다.
