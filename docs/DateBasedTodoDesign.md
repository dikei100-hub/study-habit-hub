# StudyMate 날짜별 할 일(플래너) 설계 v2 — 템플릿 방식 (DateBasedTodoDesign)

> v1(방식 B: 할 일마다 반복 스위치)에서 **방식 A(템플릿 방식)로 변경**했다.
> 이유: 학생의 실제 사용은 "매일 하는 고정 루틴은 미리 정해두고 체크만,
> 특별한 일은 그날 추가"에 가깝다. 이는 방식 A(반복 템플릿을 따로 관리)다.
>
> ★ 1단계(할 일에 date 부여)는 이미 완료됐고, 그 결과물(date/isRecurring 필드)은
>   방식 A 에서도 그대로 재사용한다. 갈아엎지 않는다.

---

## 0. 확정된 결정 (사용자)

| 항목 | 결정 |
|------|------|
| 할 일에 날짜 부여 | **완료.** 할 일은 특정 날짜(date)에 속한다. |
| 반복 방식 | **방식 A (템플릿)** — "매일 할 일 템플릿"을 따로 관리. |
| 새 날 채우기 | 새 날이 되면 템플릿이 그날 목록에 **자동으로 깔린다.**(미완료) |
| 일회성 할 일 | 그날 "+추가"로 넣음. 템플릿에는 안 들어간다. |
| 과거 날짜 | **읽기 전용.** 보기만 가능, 체크·수정·삭제 불가. |
| 미래 날짜 | **계획 가능.** 미리 일회성 할 일을 넣어둘 수 있다. |
| 반복(템플릿) 항목 삭제 | 템플릿에서 빼면 그 다음 날부터 안 깔림. 이미 깔린 오늘 것은 유지. |

---

## 1. 핵심 개념 — 두 종류의 할 일

### (A) 템플릿 할 일 (매일 반복하는 루틴)
- 학생이 **미리 만들어 두는 "매일 할 일" 목록.** (예: 영어 단어, 수학 문제집, 운동)
- 별도 테이블 `todo_templates` 에 저장된다. (날짜 없음 — 매일 공통)
- 새 날이 되면 이 템플릿들이 그날의 실제 할 일(todos)로 **복사되어 깔린다.**
  - 복사본은 미완료(isDone=false)로 새로 생성. 각 날짜의 인스턴스는 독립.
  - 오늘 "영어 단어" 체크해도, 내일 "영어 단어"는 새로 미완료로 깔림.

### (B) 일회성 할 일 (그날만의 특별한 일)
- 그날 화면에서 "+추가"로 넣는 할 일. (예: 발표 준비, 치과)
- 그 날짜(todos.date)에만 존재. 템플릿에 등록되지 않으므로 다음 날 안 나옴.

### 정리
- **todos** = 특정 날짜에 실제로 존재하는 할 일(템플릿에서 깔린 것 + 일회성). 기존 테이블 재사용.
- **todo_templates** = 매일 깔리는 루틴 정의. ★새 테이블.

---

## 2. 데이터 구조

### todos (기존, 1단계에서 date 추가 완료)
```
TodoEntity(
    id, date, title, isDone, isRecurring, sortOrder
)
```
- `isRecurring` 은 "이 인스턴스가 템플릿에서 왔는지" 표시용으로 쓸 수 있다(선택).
  방식 A 에선 필수는 아니지만, UI 에서 루틴/일회성을 구분해 보여주고 싶으면 활용.

### todo_templates (신규)
```
TodoTemplateEntity(
    id: Long,
    title: String,
    sortOrder: Int = 0,
    enabled: Boolean = true   // 잠시 끄기 지원(선택). 기본 true.
)
```
- 날짜가 없다. "매일 공통으로 깔리는 루틴"의 정의.
- 학생이 이 목록을 추가/삭제/정렬한다(관리 UI 필요).

## 3. "새 날 채우기" 로직 (핵심)

앱 진입 시(선택 날짜 = 오늘 기준):

1. 오늘 날짜의 todos 가 **이미 있으면** 아무것도 안 함(중복 방지).
2. 오늘 todos 가 **없으면**, todo_templates(enabled=true)를 순회하며
   각 템플릿을 오늘 날짜의 todos 로 복사 생성(isDone=false, isRecurring=true).
3. 템플릿이 하나도 없으면 오늘은 빈 목록으로 시작(일회성만 추가 가능).

- "며칠 안 켰다 켠 경우"도 오늘 것만 만들면 되므로 단순.
- 기존 daily_record/스트릭/코인/배지 로직은 그대로 재사용.

### 마이그레이션 참고
- 현재 시드(defaultTodos: 영어 단어 등 4개)는 방식 A 로 오면
  "기본 템플릿"으로 옮기는 게 자연스럽다. 즉 최초 실행 시 todo_templates 가
  비어 있으면 그 4개를 템플릿으로 시드 → 그 템플릿이 오늘 todos 로 깔림.

## 4. 화면별 영향

| 화면 | 변경 |
|------|------|
| 오늘 | 오늘 todos 조회(이미 됨). 할 일이 템플릿/일회성 섞여 표시. "+추가"=일회성. |
| 템플릿 관리 | ★신규 UI. 매일 할 일 목록 추가/삭제/정렬. 설정 화면 안이나 별도 진입. |
| 캘린더 | 날짜 선택 → 그 날짜 todos 표시(과거=읽기전용). |
| 통계·보상 | 영향 없음(daily_record 기반). |

- **템플릿 관리 UI 위치:** 설정 화면 안에 "매일 할 일 관리" 항목으로 넣거나,
  오늘 화면에 진입점을 두는 방법. → [결정필요] 아래 7번.

## 5. 권장 구현 순서 (재정렬 — 방식 A 기준)

> 1단계(할 일 date 부여)는 완료. 아래는 그 다음부터.

1. ✅ **[완료] todos 에 date 부여 + 오늘 날짜 조회** (버그 해결됨)
2. **템플릿 테이블 + 새 날 채우기 로직**
   - todo_templates 테이블/DAO 생성.
   - 기존 기본 4개를 템플릿으로 시드.
   - 새 날 진입 시 "오늘 todos 없으면 템플릿 복사" 로 시드 방식 교체.
   - (아직 템플릿 관리 UI 없음 — 다음 단계. 우선 시드된 기본 템플릿으로 동작 확인)
3. **템플릿 관리 UI**
   - "매일 할 일" 목록을 추가/삭제/정렬하는 화면(설정 안 또는 별도).
   - 여기서 바꾼 템플릿이 다음 날부터 반영.
4. **과거 읽기 전용**
   - 오늘 이전 날짜 todos 는 체크·수정·삭제 잠금.
5. **캘린더 → 날짜 선택 → 그 날짜 할 일**
   - 과거=읽기전용, 오늘=편집, 미래=계획.
6. **미래 계획 다듬기**
   - 미래 날짜에 일회성 할 일 추가/수정. 미래 완료 체크 정책 반영.

> 2단계까지 하면 "매일 루틴이 자동으로 깔리고 체크"가 완성된다.
> 3단계(관리 UI)까지면 학생이 자기 루틴을 직접 정할 수 있다.

---

## 6. 주의 / 리스크

- **DB 마이그레이션:** todo_templates 테이블 추가 → version 업 + 파괴적 마이그레이션(개발 단계).
- **템플릿 변경 시점:** 템플릿을 오늘 바꿔도, 오늘 이미 깔린 todos 는 그대로 두고
  "다음 날부터" 반영하는 게 안전(오늘 진행 중인 체크를 흔들지 않음).
- **중복 방지:** 새 날 채우기는 "오늘 todos 개수 == 0" 조건으로만 실행.
