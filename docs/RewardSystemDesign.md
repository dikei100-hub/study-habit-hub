# StudyMate 보상 시스템 설계 (RewardSystemDesign)

> 코인 · 배지 · 스트릭 · 스트릭 프리즈의 규칙과 데이터 구조를 정의한다.
> 이 문서는 "무엇을 만들지"의 기준이며, 구현(지시서)은 이 문서에서 파생한다.
> **확정 안 된 값은 [초안] 표시** — 개발자가 검토 후 확정한다.
>
> 최종 업데이트: 2026-07-10 (프리즈 완료 + 코인 상점 다음 순번 확정 후 재작성)

---

## 0. 한눈에 보기

| 요소 | 한 줄 정의 | 상태 |
|------|-----------|------|
| 코인 | 하루 할 일 100% 달성 시 지급되는 보상 화폐 | ✅ 완료 |
| 배지 (조건형) | 행동 조건으로 획득하는 성취 증표 | ✅ 완료 (4종) |
| 트로피 (상점형) | 코인으로 구매하는 수집 요소 | ⬜ **다음 우선 작업** |
| 스트릭 | 며칠 연속으로 하루 100%를 달성했는지의 기록 | ✅ 완료 |
| 스트릭 프리즈 | 하루 놓친 스트릭을 코인으로 방어 | ✅ 완료 |

**핵심 철학:** 관리가 아니라 응원. 벌이 아니라 보상. 놓친 날을 혼내지 않고,
코인으로 "만회할 기회"를 준다. (프리즈는 이 철학의 핵심 장치)

## 1. 코인 (Coin) ✅

### 획득 (구현 완료)
- **하루 할 일 100% 완료 시 +10코인.** (확정)
- 하루에 한 번만 지급. 이미 오늘 100% 달성해 코인을 받은 뒤,
  할 일을 추가했다가 다시 100%를 만들어도 **추가 지급 없음.**
- 부분 달성(예: 75%)에는 코인을 주지 않는다. (100%만 보상 → 목표는 "완주")

### 사용
- 스트릭 프리즈 50코인 (4번 참고) ✅ 완료
- 상점형 트로피 구매 (2-B 참고) ⬜ 미구현

### 저장 (구현 완료)
- `RewardStateEntity.coins` — 현재 보유 총량 (단일 정수)
- 획득/사용 내역 로그는 MVP 범위 밖. 총량만 관리.

## 2. 배지 / 트로피 (Badge)

두 종류로 나눈다:

### (A) 조건 달성형 배지 — 코인으로 못 삼, 행동으로만 획득 ✅ 완료

| 배지 | 획득 조건 | 상태 |
|------|-----------|------|
| 첫걸음 | 첫 하루 100% 달성 | ✅ |
| 연속 7일 | 스트릭 7일 도달 | ✅ |
| 연속 30일 | 스트릭 30일 도달 | ✅ |
| 완벽한 주 | 한 주(7일) 모두 100% | ✅ |
| 아침형 인간 | [초안] 오전에 모든 할 일 완료 (시간 기록 필요 — 후순위) | ⬜ |

- 판정 위치: `RewardCalculator.evaluateBadges`
- 획득 여부는 정산(settleStreak) 시점에 자동 갱신

### (B) 상점형 트로피 — 코인으로 구매 (수집/꾸미기용) ⬜ **다음 우선 작업**

| 트로피 | 가격 [초안] | 비고 |
|--------|------------|------|
| 브론즈 트로피 | 100코인 | |
| 실버 트로피 | 300코인 | |
| 골드 트로피 | 600코인 | |
| 특별 캐릭터 테마 | 500코인 | 캐릭터 꾸미기 (후순위) |

> 조건형(A)은 "성취의 증표", 상점형(B)은 "코인을 쓸 이유".
> 이 둘을 나눠야 코인 경제가 성립한다. (모을 목표 + 쓸 곳)

**설계 검토 필요 (구현 전):**
- 상점 UI 위치 (보상 화면 하단? 별도 탭? 별도 다이얼로그?)
- 트로피 획득 시각화 (진열장 방식? 획득 목록?)
- 구매 확인 다이얼로그 필요 여부
- 가격 확정 (위 [초안] 값 검토)
- 다음 구현 사이클 시작 시 GPT 교차 검토 후보

### 저장
- 조건형 배지: 획득 여부와 획득 날짜 — ✅ 구현됨
- 상점형: 구매 여부 — ⬜ 미구현 (테이블/필드 신설 필요)

## 3. 스트릭 (Streak, 연속 기록) ✅

### 정의
- **연속으로 "하루 100% 달성"한 날의 수.**
- 오늘 100%를 달성하면 스트릭 +1.
- 하루라도 100%를 못 하고 넘어가면 스트릭 0으로 초기화. (단, 프리즈로 방어 가능 — 4번)

### 판정 시점 — **채택된 방식: A (앱 진입 시 정산)**

앱을 켤 때 오늘 날짜를 확인하고, 마지막 정산일 이후 지나간 날들을 훑어
"그날 100%였는지"를 판정해 스트릭/코인을 갱신한다.

- 백그라운드 작업 불필요, 구현 단순.
- 대부분의 습관앱이 이 방식.
- 자정 알람(WorkManager) 방식은 배터리/권한 이슈로 MVP엔 과함 — 채택 안 함.

### 저장 (구현 완료)
- `RewardStateEntity.currentStreak` — 현재 스트릭 일수
- `RewardStateEntity.bestStreak` — 최고 스트릭 기록 (시안 "최고 기록!" 표시)
- `RewardStateEntity.lastSettledDate` — 마지막 정산 날짜
- 판정 위치: `RewardCalculator.settleStreak`

## 4. 스트릭 프리즈 (Streak Freeze) ✅ **완성**

### 개념
하루를 놓쳐 스트릭이 끊길 상황에서, **모아둔 코인으로 그 하루를 "방어"**해
스트릭을 유지한다.

### 확정 규칙

- **비용: 50코인** (5일치 코인). (확정)
- **방식: [안 2] 수동.** 앱을 켠 시점에 자동으로 다이얼로그가 뜨고 사용자가 선택.
  자동 선구매(안 1)는 채택 안 함 — 사용자에게 명시적으로 "지금 쓰시겠어요?"를 물어보는 게
  응원 컨셉과 더 잘 맞음.
- **방어 대상 = 어제 하루만.** 오늘 놓친 스트릭을 방어하지 않음 — 오늘은 아직 만회 가능하니.
- **조건** (모두 만족해야 프리즈 제안):
  1. 어제 100% 아니었고 frozen 아님
  2. 직전 연속 3일 이상 (짧은 스트릭까지 지키게 하면 코인 경제가 무너짐)
  3. 코인 50 이상 보유
  4. 오늘 아직 "아니요" 안 눌렀음 (`freezeDeclinedDate` 확인)
- **저장 순서** (원자성 보장):
  1. 어제 daily_record `frozen = true`
  2. 코인 -50
  3. settleStreak 재계산
- **"아니요" 선택 시:** `RewardStateEntity.freezeDeclinedDate = 오늘` 저장 → 그날 하루 자동 팝업 뜨지 않음.
  단 보상 화면의 스트릭 카드에서 수동 발동은 여전히 가능(마음 바뀔 여지).
- **지킬 수 없는 끊김에는 부드러운 안내 문구:**
  "어제 연속이 끊겼어요. 오늘부터 다시 시작해봐요 🌱"

### 발동 경로 (구현 완료)
- **자동 팝업:** 앱 진입 시 `HomeScreen` LaunchedEffect에서 `checkFreezeOffer` 판정 → `FreezeDialog` 표시
- **수동 발동:** 보상 화면의 `StreakCard` "코인 50으로 지키기" 버튼 (조건만 만족하면 표시)

### 저장 (구현 완료)
- `DailyRecordEntity.frozen` — 그 날이 프리즈로 방어됐는지
- `RewardStateEntity.freezeDeclinedDate` — 오늘 자동 팝업 거절 여부
- `RewardCalculator.checkFreezeOffer / applyFreeze / markFreezeDeclined`
- 프리즈로 방어한 날은 스트릭이 "유지"될 뿐, 그날 코인(+10) 지급 없음.

## 5. [토대] 날짜별 학습 기록 DB ✅

> **위 1~4가 전부 이 DB에 의존한다.** 코인·스트릭·프리즈 모두 여기서 계산됨.
> 통계 그래프·캘린더 색·개수 표시도 여기에 의존.

### 하루 요약 기록 테이블 (`DailyRecordEntity`) — 구현 완료

| 필드 | 의미 |
|------|------|
| date | 날짜 (하루 1행, 기본키) |
| totalCount | 그날의 전체 할 일 개수 |
| doneCount | 그날 완료한 할 일 개수 |
| isPerfect | 그날 100% 달성 여부 (doneCount == totalCount && totalCount>0) |
| coinAwarded | 그날 코인을 지급했는지 (중복 지급 방지) |
| frozen | 프리즈로 방어된 날인지 |

- 오늘 화면에서 할 일을 토글할 때마다 오늘 날짜 기록을 갱신
- 앱 진입 정산 시 이전 날 기록을 확정하고 스트릭/코인/배지 재계산
- 실데이터 연결 완료된 화면: 통계 (7일 그래프·이번 주·전체) · 캘린더 (링 색·%) · 보상 (코인·스트릭·배지)

### DB 스키마
- 현재 DB version 8
- `fallbackToDestructiveMigration` — 개발 중이라 마이그레이션 없이 데이터 초기화 방식

## 6. 구현 순서 (완료 표시)

작게 쪼갠 단계. 완료된 것은 ✅, 다음 순번은 ★.

1. ✅ **[토대] 날짜별 기록 DB (`daily_record`) + 오늘 화면 연동**
2. ✅ **앱 진입 정산 로직 + 스트릭 계산**
3. ✅ **코인 지급 연동** (하루 100% 시 +10, 중복 방지)
4. ✅ **보상 화면 UI (실데이터 연결)** — 코인·스트릭·배지 표시
5. ✅ **배지 획득 판정** (조건형 4종 자동)
6. ⬜ **★ 코인 상점** (상점형 트로피 구매) — **다음 우선 작업**
7. ✅ **스트릭 프리즈** (수동 방식·완성)
8. ✅ **통계·캘린더를 실데이터로 교체**

> 6번(코인 상점)이 유일하게 남은 굵직한 보상 시스템 요소.
> 이후는 폴리싱(배지 아이콘 교체·꺾은선 그래프 등) 단계.
