## 3. 배경

템플릿의 `enabled` 를 별도 지속 상태로 둔 것이 잘못된 정의였다. 지금 두 군데가
어긋난다.

**(가) 시트의 대상 날짜는 날짜별인데 `enabled` 는 전역이다.**
캘린더에서 모레를 열어 체크를 끄면 모레 목록에서 빠지는 동시에 전역 플래그가
꺼진다. 오늘 목록에는 그 항목이 그대로 있는데, 오늘 시트를 열면 체크가 꺼져
보인다. CoreRules 3장(대상 날짜)과 2장(지속성)이 서로 부딪히는 자리다.

**(나) 오늘 화면의 삭제 버튼으로 지운 항목이 시트에는 체크 켜진 채로 남는다.**
없는데 켜져 있고, 다시 넣으려면 껐다 켜야 한다.

체크박스를 **"그 날짜의 할 일 목록에 이 항목이 들어 있는가"** 를 비추는
파생값으로 바꾼다. 그러면 체크 끄기와 삭제 버튼이 같은 동작이 되고, 두 화면이
구조적으로 어긋날 수 없다.

**"며칠 쉬어가기"(한 항목을 여러 날 빼두기)는 이 사이클에서 의도적으로 포기한다.**
나중에 별도 동작으로 붙일 수 있다. 지금 규칙이 둘로 갈려 있는 쪽이 더 비싸다.

**함께 고칠 버그.** `fillFromTemplate` 의 조건이 `list && list.length > 0` 이라
빈 배열을 "기록 없음" 으로 취급한다. 오늘 할 일을 하나씩 다 지우면 새로고침 때
템플릿이 통째로 다시 깔린다.

### 커밋 2 — 수정: 템플릿 enabled 제거, 체크박스를 날짜별 파생값으로

허용 파일 **4개뿐**: `seed.ts` / `storage.ts` / `StudyStore.tsx` / `ListSheet.tsx`

#### `src/lib/seed.ts`

- `TemplateItem` 에서 `enabled` 필드를 제거한다 → `{ id, title, sortOrder }`
- `createSeedTemplates` 에서 `enabled` 를 뺀다.
- `fillFromTemplate` 의 `templates.filter((t) => t.enabled)` 를 없애고
  전체를 `sortOrder` 오름차순으로 깐다.
- 템플릿이 하나도 없을 때 아무것도 하지 않는 현재 동작은 **그대로 둔다.**

#### `src/lib/storage.ts`

- `STORAGE_KEY` 를 `"studymate.state.v2"` 로 올린다.
  **마이그레이션 코드는 쓰지 않는다.** 옛 v1 키는 지우지 말고 그대로 둔다.
- `normalizeTemplates` 가 `...t` 스프레드로 옛 `enabled` 를 흘려보내지 않도록,
  `{ id, title, sortOrder }` 만 명시적으로 뽑아 만들게 고친다.

#### `src/state/StudyStore.tsx`

- 액션 `setTemplateEnabled` 를 **`setTemplateOnDate`** 로 바꾼다.
  페이로드는 `{ date, id, on }`.
  이름을 남겨두면 의미가 바뀐 걸 놓치게 되므로 반드시 바꾼다.
- 이 액션은 **`templates` 배열을 더 이상 수정하지 않는다.**
  그 날짜의 목록만 바꾼다. ← **이번 사이클의 핵심**
  - `on`: 이미 있으면 아무것도 안 함. 없으면 삽입.
  - `off`: 그 날짜 목록에서 제거.
  - 시작할 때 `materialize(state, date)` 를 호출하는 현재 구조는 유지한다.
- 켤 때의 **삽입 위치 계산은 지금 로직을 그대로** 쓰되, 순위 기준을
  "enabled 인 템플릿" 이 아니라 **"전체 템플릿"** 의 `sortOrder` 순으로 바꾼다.
  기존 항목은 재정렬하지 않는다.
- `addTemplate` 에서 `enabled: true` 를 뺀다.
  나머지(맨 위 삽입, 빈 문자열 무시)는 그대로.
- 셀렉터 **`isTemplateOn(date, id): boolean`** 을 추가한다.
  `previewFor(date)` 결과에 `todoIdFor(date, id)` 가 들어 있는지로 판정한다.
  `ListSheet` 가 직접 계산하지 않고 이것만 쓰게 한다 (판정 로직을 스토어 한 곳에).
- store API 의 `setTemplateEnabled` 를 `setTemplateOnDate` 로 바꾸고
  `canManage` 가드는 유지한다.
- `previewFor` 는 손대지 않는다. `fillFromTemplate` 이 바뀌면서 자동으로 따라온다.

#### `src/components/app/ListSheet.tsx`

- `tpl.enabled` 를 `isTemplateOn(date, tpl.id)` 로 교체한다
  (체크 표시·아이콘 조건 모두).
- `onClick` 을 `setTemplateOnDate(date, tpl.id, !on)` 로 바꾼다.
- `aria-label` 을 2절 [고정 문자열] 의 두 문구로 교체한다.
- **색·여백·레이아웃은 한 줄도 바꾸지 말 것.**

### 커밋 3 — 수정: 빈 목록을 존중하고 재시딩하지 않음

허용 파일: `seed.ts` / `StudyStore.tsx`

- `fillFromTemplate` 의 조건을 길이가 아니라 **키 존재 여부**로 바꾼다.
  이미 키가 있으면(빈 배열이라도) 아무것도 하지 않는다.
- `statsFor` 의 `hasRecord: !!list` 를 빈 배열일 때 `false` 가 되도록 고친다.

> ★ **이 둘은 서로 다른 질문이므로 기준을 일부러 다르게 둔다. 통일하지 말 것.**
>
> | 함수 | 묻는 것 | 기준 |
> |---|---|---|
> | `fillFromTemplate` | 이 날짜를 만든 적이 있나 | 키 존재 |
> | `statsFor` | 화면에 보여줄 기록이 있나 | 길이 > 0 |
>
> 결과: 사용자가 비운 날은 다시 깔리지 않고, 달력에는 0% 링 대신 `-` 가 뜨며,
> 스트릭은 그날에서 끊긴다. **이게 의도한 동작이다.**
> 주석으로 이 이유를 짧게 남길 것.
