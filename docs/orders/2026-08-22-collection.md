## 3. 배경 — 문서가 실제와 달랐다

`CrossTrack_AppSpec.md` 4-4 는 보상 화면의 배지 격자에 **"획득/미획득(잠금)을 모두

그런데 **실제 안드로이드 앱은 다르다.** 스크린샷으로 확인했다.

| 화면 | 실제 내용 |
|---|---|
| 보상 탭 | 칭찬 카드 · 컬렉션 진입 버튼 · **획득한 배지만** · 획득한 트로피 |
| 내 컬렉션 | 코인 잔액 · **트로피 3종** (구매/조건) · **배지 12종 전체** (미획득 회색 + 조건) |

문서가 아니라 **실제 화면이 기준**이다. 웹도 이 구조로 맞춘다.

동시에 지금 웹에는 **배지 조건이 어디에도 없다.** "노력왕" 이 무엇을 해야 받는지
알 방법이 없다. `CrossTrack_Lessons.md` 1-3 이 지적한 문제가 그대로다 —
"완벽한 날 50일" 이 무슨 뜻인지 앱 어디에도 정의가 없어 의미가 안 와닿았다는 것.

## 6. 구현

### 커밋 1 — 기능: 배지 조건과 트로피 상태 셀렉터

허용 파일: `src/lib/rewards.ts`, `src/state/StudyStore.tsx`, 이 지시서 파일

#### `src/lib/rewards.ts`

- `BADGE_REQUIREMENTS: Record<BadgeCode, string>` 를 **`BADGE_NAMES` 바로 옆**에
  둔다. 5절 표대로.
  - 이름과 조건이 한자리에 있어야 나중에 어긋나지 않는다.
- `TROPHY_NAMES: Record<string, string>` 를 `TROPHY_PRICES` 옆에 둔다.
- `BadgeProgress` 에 `requirement: string` 을 더한다. `badgeProgress` 가 채운다.
- `trophyProgress(rewards, coins)` 순수 함수를 추가한다. 세 트로피를
  **브론즈 → 실버 → 골드 순서**로 돌려준다. 각 항목:

```
{ id, name, price, owned, blockedBy: string | null, affordable: boolean }
```

- `blockedBy` 는 **이전 등급을 아직 안 샀을 때** 그 트로피의 **이름**이다.
  살 수 있으면 `null`. 브론즈는 항상 `null`.
- `affordable` 은 코인이 가격 이상인지.
- **판정 로직만 둔다.** 구매는 C-2 다. 상태를 바꾸는 코드를 쓰지 말 것.

#### `src/state/StudyStore.tsx`

- 셀렉터 `trophyProgress` 를 노출한다. `coins` 를 넘겨 호출한다.
- 기존 셀렉터를 건드리지 말 것.

---

### 커밋 2 — 기능: 내 컬렉션 시트 신설

허용 파일: `src/components/app/CollectionSheet.tsx`(신규),
`src/routes/rewards.tsx`

- **`ListSheet`·`SettingsSheet` 와 같은 바텀시트 구조**를 따른다. 새 패턴 금지.
  내용이 길어 스크롤이 필요하다. 시트 안쪽만 스크롤되게 하고 `safe-area-inset-bottom`
  패딩을 유지할 것.
- **헤더:** `내 컬렉션` 과 오른쪽에 코인 잔액. 코인은 알약 모양으로 작게.
- **트로피 섹션 (`트로피`)** — 3종을 **세로 목록**으로. 각 줄은 가로 배치:
  `Trophy 이미지 | 이름 | 상태`
  - 보유 → 원색 이미지 + `획득!`
  - 미보유 → 회색조 이미지 + `구매하기 · {가격}코인`
    - `blockedBy` 가 있으면 그 아래 `{이름} 먼저`
    - 아니고 `affordable` 이 거짓이면 `코인 부족`
  - ★ **이번 사이클에서 구매 버튼은 전부 비활성**이다. 눌러도 아무 일이 없어야 한다.
    `구매하기 · {가격}코인` 은 버튼이 아니라 **텍스트**로 두어도 좋다. 살 수 있는
    상태라도 마찬가지다. 실제 구매는 C-2 에서 붙인다.
- **배지 섹션 (`배지`)** — 12종을 **세로 목록**으로. 각 줄:
  `Badge 이미지 | 이름 | 조건 | 획득!`
  - 획득 → 카드 배경을 포인트 톤(`lilac`)으로, 이미지 원색, 오른쪽 `획득!`
  - 미획득 → 카드 배경 `surface`, 이미지 회색조, `획득!` 없음. **조건은 보인다.**
  - 이름은 굵게, 조건은 작고 흐리게 이름 옆에 둔다.
- `rewards.tsx` 의 `내 컬렉션 모두 보기` 버튼에 `onClick` 을 붙여 이 시트를 연다.
  열림 상태는 `rewards.tsx` 안에서 관리한다. 전역 상태를 만들지 말 것.
- 새 색·새 그림자 정의 금지. 등록된 토큰만.

### 커밋 3 — 기능: 보상 탭을 획득한 것만 보이게

허용 파일: `src/routes/rewards.tsx`

- 배지 섹션 제목을 `획득한 배지` 로 두고 **획득한 것만** 그린다.
  - 격자 모양은 B-2 것을 유지한다.
  - 하나도 없으면 5절의 빈 상태 문구를 보인다.
  - `{획득} / 12` 표시는 **뗀다.** 전체가 안 보이므로 분모가 어색하다.
- **보유 코인 카드를 뗀다.** 코인은 컬렉션 헤더로 옮겼다.
  - 보상 탭은 "성취를 본다", 컬렉션은 "모으고 쓴다" 로 역할을 나눈다.
    코인은 쓰는 곳 옆에 있는 편이 자연스럽고, 실제 안드로이드도 그렇다.
- 트로피 섹션은 지금 그대로 둔다 (보유한 것만, 없으면 빈 상태).
- 칭찬 카드·컬렉션 버튼은 손대지 말 것.

### 커밋 4 — 문서

허용 파일: `docs/CoreRules.md`, `docs/CrossTrack_AppSpec.md`,
`docs/sessions/2026-08-22.md`

- **`CrossTrack_AppSpec.md` 4-4 를 바로잡는다.** "배지 격자에 획득/미획득을 모두
  표시" 는 실제와 다르다. 본문을 고치지 말고 **그 줄 아래에 정정 주석**을 단다.
  이 문서는 안드로이드 트랙의 기록이므로 원문을 지우지 않는다.

> ※ 실제 앱과 다름 — 보상 탭에는 **획득한 배지만** 나오고, 미획득과 조건은
> **내 컬렉션**에 있다. 웹은 실제 화면을 따랐다.

- `CoreRules` 7장 화면 구성에 컬렉션을 적는다.

> 보상 탭의 `내 컬렉션 모두 보기` 를 누르면 컬렉션 시트가 열린다.
> 보상 탭은 **획득한 것만** 보이고, 컬렉션에 트로피 3종과 배지 12종 전부가
> 조건과 함께 나온다. 미획득은 회색조로 흐리게 두되 숨기지 않는다 — 목표가
> 보여야 동기가 된다.
>
> 배지 조건 문구는 **사용자 말로 풀어쓴다.** 안드로이드는 `완벽한 날 50일` 처럼
> 내부 용어를 그대로 노출해 뜻이 안 통했다(`Lessons` 1-3). 웹은
> `모두 완료한 날 50일` 로 쓴다. 문구는 `rewards.ts` 의 `BADGE_REQUIREMENTS` 한 곳에 둔다.

- 10장 남은 이슈에서 **"컬렉션 화면 미구현"을 해결됨으로 옮긴다.** 코드 커밋 해시로.
- 10장에 새 이슈 한 줄을 남긴다.

> 컬렉션의 트로피 구매 버튼이 비활성이다. 구매는 C-2 에서 붙인다.

화면 확인은 사용자가 한다.

| # | 케이스 | 기대 |
|---|--------|------|
| 1 | `BADGE_REQUIREMENTS` 12개 | 5절 표와 **한 줄씩** 일치. 표로 보일 것 |
| 2 | 트로피 아무것도 없음, 코인 0 | 브론즈 `blockedBy: null`·`affordable: false`, 실버·골드는 `blockedBy` 에 이전 이름 |
| 3 | 코인 150, 트로피 없음 | 브론즈 `affordable: true`, 실버 `blockedBy: "브론즈 트로피"` |
| 4 | 브론즈 보유, 코인 350 | 브론즈 `owned`, 실버 `affordable: true`·`blockedBy: null`, 골드 `blockedBy: "실버 트로피"` |
| 5 | 셋 다 보유 | 전부 `owned`, `blockedBy` 모두 `null` |
| 6 | 순서 | 항상 브론즈 → 실버 → 골드 |
| 7 | `badgeProgress` 에 `requirement` | 12개 모두 빈 문자열이 아님 |
| 8 | 구매 코드 없음 | `git grep -n "purchase\|buy" -- src/` 에 상태를 바꾸는 코드가 없음 |
| 9 | `npx tsc --noEmit` | 통과 |
| 10 | `npm run lint` | 기존 CRLF 외 새 오류 없음 |

2~5 번이 핵심이다. **`blockedBy` 와 `affordable` 이 동시에 걸리는 경우**(이전 등급도
없고 코인도 없음)에 어느 문구가 나오는지 확인할 것 — `blockedBy` 가 우선이다.

## 10. 사용자에게 안내할 것 (보고에 포함)

- 보상 탭 — 배지가 **받은 것만** 보인다. 코인 카드는 컬렉션으로 옮겼다.

- 조건 문구가 사용자 말로 읽히는지 봐 주시라고 안내할 것. 어색한 것이 있으면
