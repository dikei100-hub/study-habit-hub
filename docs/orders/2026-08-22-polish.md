## 3. 배경

기능은 다 붙었다. 실사용에서 나온 다듬을 것 셋을 한 사이클에 처리한다.
성격이 다르므로 **커밋을 나눈다.**

### (1) 보상 탭에 코인이 안 보인다

C-1 에서 "코인은 쓰는 곳 옆에" 라는 이유로 보상 탭의 코인 카드를 떼고 컬렉션
헤더로 옮겼다. **써 보니 아니었다.** 성취를 확인하러 보상 탭에 갔는데 코인만
안 보이는 것이 어색하다.

### (2) `연속 달성` 이라는 문구가 뜻과 어긋난다

스트릭은 **습관 축**(그날 하나라도 완료)인데 "달성" 은 **완벽 축**(100%)을
암시한다. `CrossTrack_Lessons.md` 1-4 의 **"단어의 함의를 조심하라"** 에 해당한다.
안드로이드가 "꾸준히" 라는 말을 썼다가 '연속' 을 암시해 폐기한 것과 같은 종류다.

### (3) 막대그래프가 기록 없는 날과 0% 달성한 날을 구분하지 못한다

`stats.tsx` 가 `d.rate > 0` 일 때만 막대를 그려서, **담았는데 하나도 못 한 날**과
**아예 앱을 안 연 날**이 똑같이 빈 자리로 보인다. 캘린더는 `-` 로 구분하는데
같은 상태를 두 화면이 다르게 답한다.

`last7Days` 가 `rate` 만 담고 `hasRecord` 를 버리기 때문이다. `statsFor` 는
이미 `hasRecord` 를 돌려준다.

### 커밋 1 — 기능: 보상 탭에 코인 표시

허용 파일: `src/routes/rewards.tsx`, 이 지시서 파일


- **`CollectionSheet` 헤더의 알약과 같은 모양**으로 만든다. 들어가서도 이어져
  보여야 한다. 색·크기·아이콘을 그대로 맞출 것. 새 색·새 그림자 금지.

- 버튼의 위치·높이·배경·문구는 그대로 둔다.
- 코인 값은 스토어의 `coins` 셀렉터를 쓴다. 새 계산을 하지 말 것.

> 같은 알약 마크업이 두 파일에 생긴다. 지금은 두 곳뿐이고 공통 컴포넌트로

### 커밋 3 — 수정: 막대그래프가 기록 없는 날을 구분한다

허용 파일: `src/state/StudyStore.tsx`, `src/routes/stats.tsx`

#### `StudyStore.tsx`

- `last7Days` 의 각 항목에 **`hasRecord: boolean`** 을 더한다.
  `statsFor` 가 이미 돌려주는 값을 그대로 싣는다. **새로 계산하지 말 것.**
- 타입 선언도 함께 고친다.
- 그 밖의 셀렉터를 건드리지 말 것.

#### `stats.tsx`

세 갈래로 그린다.

| 그날 | 막대 |
|---|---|
| **기록 없음** (`hasRecord` 거짓) | **아무것도 그리지 않는다** (지금과 같음) |
| **0% 달성** (기록 있고 `rate === 0`) | **바닥에 붙은 얇은 막대.** 흐린 색 |
| **1% 이상** | 지금 그대로 |

- 0% 막대는 **높이를 아주 낮게**(4px 안팎) 두고 색을 흐리게 해서, 1% 이상과
  헷갈리지 않게 한다. "담았는데 아직 못 했다" 가 읽히면 된다.
- 등록된 토큰만 쓸 것. 새 색을 만들지 말 것.
- 날짜 라벨·퍼센트 표시·카드·간격은 손대지 말 것.
- 지금 `Math.max(d.rate, 8)` 로 최소 높이를 주는 부분이 있다. 1% 이상에만
  적용되도록 두고, 0% 는 별도로 처리할 것.

## 7. 검증

`rolldown` 으로 번들해 Node 에서 확인한다. **dev 서버를 쓰지 말 것.**

| # | 케이스 | 기대 |
|---|--------|------|
| 1 | `git grep -n "연속 달성"` | 결과 없음 |
| 2 | `연속 공부` 등장 위치 | `stats.tsx`·`index.tsx` 세 자리 |
| 3 | 보상 탭 렌더 | 컬렉션 버튼 안에 `coins` 값이 있음 |
| 4 | 코인 알약 마크업 | `CollectionSheet` 헤더의 것과 클래스가 같음. **나란히 놓고 보일 것** |
| 5 | ★ `last7Days` 항목 | 7개 모두 `hasRecord` 를 가짐 |
| 6 | ★ 기록 없는 날 | `hasRecord: false`, `rate: 0` |
| 7 | ★ 담았지만 0개 완료 | `hasRecord: true`, `rate: 0` |
| 8 | 3개 중 1개 완료 | `hasRecord: true`, `rate: 33` |
| 9 | ★ 렌더 — 기록 없는 날 | 막대 없음 |
| 10 | ★ 렌더 — 0% 달성한 날 | **얇은 막대 있음** |
| 11 | 렌더 — 33% | 지금과 같은 막대 |
| 12 | `statsFor` 반환 형태 | 변경 없음 (다른 화면이 전부 쓴다) |
| 13 | `npx tsc --noEmit` | 통과 |
| 14 | `npm run lint` | 기존 CRLF 외 새 오류 없음 |

**6·7 이 이번 변경의 핵심이다.** 두 경우가 지금은 화면에서 똑같이 보인다.

9~11 은 `react-dom/server` 로 SSR 렌더해 마크업을 뽑아 **세 경우를 나란히 놓고**
비교할 것. D-1 에서 쓴 방식과 같다.

★ D-1 의 교훈 — 그때 체크 표시를 `<svg>` 존재로 판정했다가 휴지통 아이콘까지
잡혔다. **지표가 실제로 그것만 잡는지 먼저 확인할 것.** 결과가 예상과 다르면
코드보다 측정 도구를 먼저 의심하라.
