### 이번 사이클의 핵심 원칙 — "한 번 준 것은 뺏지 않는다"

`RewardNotes` [1]·[2] 가 같은 말을 한다.

- **배지:** 조건은 매번 재계산하되, **미획득 → 획득으로만 승격한다.** 강등 없음.
  오늘 100% 달성해 "첫걸음"을 받은 뒤 체크를 풀어도 배지는 남는다.
- **코인:** 완벽한 날마다 10 지급하되 **하루 1회만.** 체크를 풀어도 **회수하지 않는다.**

"관리가 아니라 응원" 이 이 규칙의 근거다. 준 것을 도로 뺏으면 응원이 아니다.

### 안드로이드와 다르게 갈 한 가지

`RewardNotes` [6] 2번이 "코인 지급 여부를 **그날 기록의 플래그**로 관리해서
코인 로직이 일별 기록과 강하게 결합됐다" 는 것을 아쉬움으로 꼽았다.

웹은 그러지 않는다. **"코인을 지급한 날짜 목록"** 을 따로 둔다. 그러면 날짜별
할 일 기록은 순수하게 할 일만 담고, 보상은 보상끼리 모인다.

### 커밋 1 — 수정: 보상 저장 구조 추가

허용 파일: `src/lib/storage.ts`, 이 지시서 파일

rewards: {
  earnedBadges: { code: string; date: string }[];   // 획득한 배지와 획득일
  coinAwardedDates: string[];                       // 코인을 지급한 날짜

#### ★ 저장 키를 올리지 말 것

**기존 데이터가 살아남는다.** 키를 올리면 지금 쌓인 기록이 날아간다.

- `normalizeRewards(value)` 를 `normalizeTemplates` 와 같은 방식으로 만든다.
  없거나 깨졌으면 세 배열이 모두 빈 값인 상태를 돌려준다.
- 배열 요소도 형태를 검사해 걸러낸다. 스프레드로 알 수 없는 필드가 흘러들지
  않도록 필요한 필드만 명시적으로 뽑을 것 (`normalizeTemplates` 의 선례를 따를 것).
- `createInitialState()` 도 빈 `rewards` 를 포함하게 한다.
- `isValid` 는 건드리지 말 것. `todosByDate` 검사 그대로 둔다.

### 커밋 2 — 기능: 코인·배지 판정

허용 파일: `src/lib/rewards.ts`(신규), `src/state/StudyStore.tsx`

#### `src/lib/rewards.ts` 신규 — 순수 함수만 둔다

React 를 import 하지 말 것. 스토어에서 호출만 한다.
**순수 함수로 두어야 검증에서 실제로 돌릴 수 있다.**

##### 배지 정의

- **내부 식별자는 의미 중립으로.** `b01` ~ `b12` 같은 뜻 없는 코드를 쓴다.
  `streak_7` 처럼 의미를 담으면, 나중에 기준을 바꿀 때 식별자와 실제가 어긋난다.
  안드로이드가 정확히 그 함정에 빠졌다 (`Lessons` 2-5).
- 표시 이름은 **별도 맵**으로 관리한다. 이름을 바꿔도 획득 데이터가 안전하다.
- 12종의 조건은 `CoreRules` 8장 표를 그대로 따른다. 각 배지에 축(습관/완벽/누적/상점)도 함께 둔다.

##### 집계 함수

`todosByDate` 와 `today` 를 받아 아래를 계산한다. **`today` 보다 뒤인 날짜는 전부 제외한다.**

| 값 | 정의 |
|---|---|
| 완벽한 날 수 | 예정 개수 > 0 **그리고** 완료 == 예정 인 날의 수 |
| 공부한 날 수 | 완료 개수 ≥ 1 인 날의 수 |
| 누적 완료 개수 | 모든 날의 완료 개수 합 |
| 하루 5개 이상 완료한 날 수 | 완료 개수 ≥ 5 인 날의 수 |
| 완벽한 주 | 오늘 포함 최근 7일이 **모두 기록 존재 && 모두 완벽** |

★ **예정 0개인 날은 완벽이 아니다.** 공짜 완벽을 주지 않는다 (`RewardNotes` [4]).
따라서 최근 7일에 예정 0개인 날이나 기록 없는 날이 하나라도 끼면 "완벽한 주" 불성립.

★ **"하루 5개 이상"은 완료 개수 기준**이다. 예정 개수가 아니다 (`RewardNotes` [4]).

##### `settleRewards(todos, rewards, today, streakBest)` — 정산

`CoreRules` 8장의 **정산 순서: 코인 → 스트릭 → 배지** 를 지킨다.
스트릭은 이미 `streakFor` 가 계산하므로 그 결과(`best`)를 인자로 받는다.

1. **코인.** `today` 이하의 날 중 완벽한 날인데 `coinAwardedDates` 에 없으면 추가한다.
   - **날짜를 목록에서 빼는 코드를 절대 넣지 말 것.** 회수는 없다.
   - 목록에 있는 날짜는 다시 판정하지 않는다. 이것이 하루 1회 지급을 보장한다.
2. **배지.** 12종을 판정해 **조건을 만족했는데 `earnedBadges` 에 없는 것만** 추가한다.
   획득일은 `today`.
   - **이미 획득한 배지는 손대지 않는다.** 조건이 거짓이 되어도 빼지 않는다.
   - `b12`(첫 트로피)는 `purchasedTrophies` 가 비어 있으므로 B-3 까지 항상 미획득이다.
3. 바뀐 게 없으면 **원래 객체를 그대로 돌려준다.** 매번 새 객체를 만들면 불필요한
   저장·리렌더가 일어난다.

##### 코인 잔액

`coinAwardedDates.length * 10 − 구매한 트로피 값의 합` 으로 **파생**한다.
잔액을 따로 저장하지 않는다. 지급 날짜가 지워지지 않으므로 잔액도 줄지 않는다.
B-3 까지 트로피는 없으니 사실상 `length * 10` 이다.

#### `src/state/StudyStore.tsx`

- **리듀서에서 정산한다.** `todosByDate` 를 바꾸는 액션 뒤에 `settleRewards` 를
  통과시켜 `rewards` 를 갱신한다. 리듀서는 단일 스레드라 이 자체로 원자적이다.
  별도 이펙트로 빼지 말 것 — 이중 실행 위험이 생긴다.
- `hydrate` 직후에도 한 번 정산한다. 앱을 며칠 만에 열었을 때를 위해서다.
- 셀렉터로 아래를 노출한다. 화면 연결은 B-2 에서 한다.
  - `coins: number` — 파생 잔액
  - `earnedBadges` — 저장된 목록 그대로
  - `badgeProgress` — 12종 각각의 획득 여부 (미획득 포함 전체 목록)
- 기존 셀렉터(`streak`·`weekDiff`·`statsFor` 등)를 건드리지 말 것.

#### 화면은 손대지 않는다

`rewards.tsx` 는 여전히 `mockData` 를 쓴다. **이번 사이클에서 화면 변화는 없다.**
그것이 정상이다.

## 6. 검증

`rolldown` 으로 번들해 Node 에서 확인한다. **dev 서버를 띄우지 말 것.**
순수 함수에 합성 데이터를 넣어 `today` 를 인자로 넘길 것.

| # | 케이스 | 기대 |
|---|--------|------|
| 1 | 옛 payload(`rewards` 없음)를 `loadState` | 빈 `rewards` 로 채워지고 `todosByDate` 는 보존 |
| 2 | `rewards` 가 깨진 값 | 빈 `rewards`, 앱이 죽지 않음 |
| 3 | 오늘 100% | `coinAwardedDates` 에 오늘, `coins === 10` |
| 4 | ★ 같은 상태로 정산을 3번 반복 | `coins` 가 **10 그대로.** 30 이 되면 실패 |
| 5 | ★ 100% 뒤 체크 하나 해제 | `coins` **10 유지**, 오늘이 목록에 **남아 있음** |
| 6 | ★ 100% 뒤 체크 해제 | `b01`(첫걸음)이 **여전히 획득 상태** |
| 7 | 완벽한 날 3일 | `coins === 30` |
| 8 | 예정 0개인 날 | 완벽으로 세지 않음, 코인 없음 |
| 9 | 최근 7일 중 하루가 예정 0개 | "완벽한 주" 불성립 |
| 10 | 하루 5개 완료 (예정 8개) | "하루 5개 이상" 에 **포함** (완료 기준) |
| 11 | 하루 예정 5개 중 3개 완료 | "하루 5개 이상" 에 **불포함** |
| 12 | 미래 날짜에 완료 기록이 있어도 | 집계에서 제외 |
| 13 | 바뀐 게 없을 때 | `settleRewards` 가 **같은 객체 참조**를 돌려줌 |
| 14 | 12종 전부 | 조건을 채운 만큼만 획득, 나머지는 미획득으로 목록에 존재 |
| 15 | `npx tsc --noEmit` | 통과 |
| 16 | `npm run lint` | 기존 CRLF 외 새 오류 없음 |

**4·5·6 이 이번 사이클의 핵심이다.** 하나라도 실패하면 "한 번 준 것은 뺏지
않는다" 가 깨진 것이다.

1번도 중요하다. 여기서 실패하면 **사용자 데이터가 날아간다.**
