## 3. 배경

컬렉션에 트로피 3종이 가격·조건과 함께 나오지만 **버튼이 비활성**이다. 코인은
쌓이는데 쓸 곳이 없다. 이번에 붙인다.

이번 사이클은 지금까지와 성질이 다르다. **사용자 재화를 처음으로 차감한다.**
지금까지의 데이터 변경은 대부분 읽기 전용 계산이었고, 틀려도 다시 계산하면 됐다.
구매는 되돌릴 수 없다.

`CrossTrack_Lessons.md` 3-7 이 안드로이드판의 프리즈(코인 차감) 규칙에서
**"적용 순서 + 원자성 + 이중 처리 방지"** 를 강조했다. 같은 주의가 필요하다.

### 웹은 차감하지 않는다 — 구조가 다르다

코인 잔액은 **저장값이 아니라 파생값**이다.

```
잔액 = 코인 지급 날짜 수 × 10 − 구매한 트로피 값의 합
```

그래서 구매는 **`purchasedTrophies` 에 하나 더하는 것**이 전부다. 잔액을 직접
빼는 코드를 쓰지 않는다. 이중 차감이 구조적으로 불가능하다.

막아야 할 것은 **같은 트로피를 두 번 사는 것** 하나뿐이다.

### 첫 구매는 배지도 함께 준다

`b12`(첫 트로피)의 조건이 "트로피 첫 구매" 다. 브론즈를 사면 트로피와 배지를
**동시에** 받는다. 축하 팝업을 따로 만들면 두 개가 겹친다.

그래서 **기존 배지 축하를 확장해 트로피도 함께 보여준다.** 새 팝업을 만들지 않는다.

## 6. 구현

### 커밋 1 — 기능: 구매 액션

허용 파일: `src/lib/rewards.ts`, `src/state/StudyStore.tsx`, 이 지시서 파일

#### `src/lib/rewards.ts`

- `canPurchase(rewards, coins, id): boolean` 순수 함수를 추가한다.
  `trophyProgress` 와 **같은 판정**을 쓴다. 두 곳에서 따로 계산하지 말 것 —
  화면이 살 수 있다고 보여주는데 액션이 거부하면 안 된다.
  조건: 아직 없음 **그리고** `blockedBy` 없음 **그리고** 잔액 ≥ 가격.

#### `src/state/StudyStore.tsx`

액션 `purchaseTrophy` 를 추가한다.

1. **리듀서 안에서 조건을 다시 검사한다.** `canPurchase` 를 부른다.
   거짓이면 상태를 그대로 돌려준다. 화면의 가드만 믿지 말 것 —
   실행 시점에 재검사하는 것이 `Lessons` 3-7 의 요구다.
2. `purchasedTrophies` 에 id 를 **더한다.** 잔액을 빼는 코드를 쓰지 말 것.
   파생값이므로 저절로 줄어든다. 이 이유를 주석으로 남길 것.
3. 그 뒤 `settleRewards` 를 통과시킨다. `b12` 가 여기서 붙는다.
   **정산을 직접 흉내 내지 말 것.** 기존 경로를 그대로 쓴다.
4. 새로 받은 것을 `justEarned` 에 담는다 (아래 참고).

#### `justEarned` 확장

지금은 배지 코드 배열이다. 트로피도 담아야 한다.

```
justEarned: { kind: "badge" | "trophy"; name: string }[]
```

- **표시 이름까지 담는다.** 팝업이 코드로 이름을 되찾지 않게 한다.
- **저장하지 않는다.** `saveState` 가 세 필드만 고르는 구조는 그대로다.
  이번에 그 구조를 건드리지 말 것.
- `hydrate` 정산에서는 담지 않는다. 지금 규칙 그대로.
- 액션 이름 `dismissBadgeCelebration` 은 이제 배지만이 아니므로
  `dismissCelebration` 으로 바꾼다.

store API 에 `purchaseTrophy(id)` 를 노출한다. 날짜 가드는 필요 없다.

### 커밋 3 — 기능: 컬렉션의 구매 버튼과 확인

허용 파일: `src/components/app/CollectionSheet.tsx`

#### 먼저 중복을 없앤다

지금 트로피 줄에 `구매하기 · {가격}코인` 이 **두 군데** 있다. 오른쪽에 하나,
그 아래 안내줄에 또 하나. 상태 표시를 **한 자리로 합친다.**

| 상태 | 오른쪽에 보이는 것 |
|---|---|
| 보유 | `획득!` |
| 선행 조건 미충족 | `{이전 이름} 먼저` (회색 텍스트) |
| 코인 부족 | `코인 부족` (회색 텍스트) |
| 살 수 있음 | **`구매하기 · {가격}코인` 버튼** |

#### 2단계 확인

**`SettingsSheet` 의 데이터 초기화와 같은 방식**을 따른다. 새 패턴 금지.

- `구매하기` 를 누르면 **같은 자리에서** `{이름}를 구매할까요?` 와
  `네, 구매할게요` / `취소` 로 바뀐다.
- 브라우저 `confirm()` 을 쓰지 말 것.
- 한 번에 **한 줄만** 확인 상태가 된다. 다른 트로피를 누르면 앞의 것은 접힌다.
- `취소` 하거나 시트를 닫으면 확인 상태가 풀린다.
- `네, 구매할게요` → `purchaseTrophy(id)`. 시트는 **열린 채로 둔다.**
  구매한 줄이 `획득!` 로 바뀌고 다음 등급이 살 수 있게 되는 것을 그 자리에서 본다.

#### 그 밖에

- 헤더의 코인 잔액이 구매 후 줄어든 값으로 다시 그려지는지 확인할 것.
- 배지 섹션·레이아웃·색은 손대지 말 것.

## 10. 사용자에게 안내할 것 (보고에 포함)

- 컬렉션에서 살 수 있는 트로피에 **버튼**이 생긴다. 누르면 그 자리에서
  `구매할까요?` 로 바뀌고, 확인하면 구매된다.
- **첫 구매는 트로피와 `첫 트로피` 배지를 함께 준다.** 축하 팝업에 둘 다 나온다.
