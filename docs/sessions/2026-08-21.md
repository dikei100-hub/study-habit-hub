## 2. 해결한 이슈

### 시드 데이터 고정 날짜 (CoreRules 10장 1번, `bab45dc`)

`createSeedTodos` 가 `calendarMonth({ 2026, 8, today: 19 })` 를 절대 날짜로 써서
기록을 2026년 8월에 박아넣고 있었다. 달이 바뀌면 캘린더와 통계가 빈다.

`monthRecords` 의 키를 절대 일자가 아니라 **`calendarMonth.today` 기준 상대
오프셋**으로 재해석하고 `getStudyDate(new Date())` 로 얻은 오늘에 다시 적용했다.

- 기록이 항상 오늘 또는 과거에만 떨어진다. 미래에 완료된 할 일이 생기지 않는다.
- 12~15일 연속 100% 구간 등 데모 데이터의 모양이 보존된다.
- `todayTasks` 가 정확히 오늘 칸에 들어가면서 `fillFromTemplate` 이 오늘에 대해
  no-op 이 된다. 시드와 템플릿 목록이 갈라지던 현상이 사라졌다.

월 넘김·연 넘김·윤년·새벽 4시 이전 진입을 실제 모듈로 확인했다.

### 시드 첫날 id 불일치 (문서에 없던 버그, `8e68772`)

`todayTasks` 를 그대로 복사해 id 가 `t1/t2/t3` 였다. 리듀서는 템플릿 관련 동작을
전부 `todoIdFor(date, templateId)` = `` `${date}-${templateId}` `` 로 조회하므로
시드 첫날에는 매칭이 전부 실패했다. 증상 세 가지:

- 리스트 관리에서 체크를 꺼도 오늘 할 일에서 사라지지 않음 (2장 위반)
- 껐다 다시 켜면 같은 제목이 완료/미완료 두 개로 **중복 추가**
- 휴지통으로 지워도 오늘 할 일에는 영구히 남음 (3장 위반)

시드 오늘 할 일을 템플릿에서 깔린 항목으로 취급하고 id 를 템플릿 파생 형식으로
발급했다. 대응 템플릿은 **제목으로** 찾는다. 인덱스로 짝지어도 현재 데이터에선
같지만, `mockData` 에서 순서가 바뀌면 조용히 엉뚱한 템플릿에 붙기 때문이다.

### 체크를 다시 켤 때 순서 어긋남 (문서에 없던 버그, `e999230`)

`setTemplateEnabled` 의 켜기 분기가 항목을 목록 맨 뒤에 붙이고 있었다.
템플릿 `sortOrder` 오름차순 기준으로 **뒤에 오는 첫 항목 앞**에 끼워 넣도록 고쳤다.
`fillFromTemplate` 이 다음 날 목록을 만들 때 쓰는 기준과 같아서 날짜별로 순서가
갈라지지 않는다.

기존 항목은 재정렬하지 않는다. 목록 전체를 정렬하면 이미 어긋나 있던 순서까지
함께 바뀌어 관계없는 항목이 튀는 것처럼 보인다.

> **확인 과정 메모** — 처음 보고된 증상은 "리스트 관리에서 새 항목을 추가하면
> 맨 아래에 붙는다" 였다. 실제 리듀서를 돌려보니 `addTemplate` 은 추가 직후·
> 새로고침 후·다음 날까지 **이미 맨 위를 지키고 있었다.** 맨 아래로 가는 경로는
> 체크 껐다 켜기 하나뿐이었다. 8080 포트에 이전부터 떠 있던 dev 서버가 있어서
> 오래된 번들을 보고 계셨을 가능성이 있다.

### 캘린더 월 이동 (CoreRules 10장 2번, `105f36f`)

`year`/`month` 가 `today` 에서 파생된 상수라 바뀔 수 없었고 버튼에 `onClick` 이
없었다. 보고 있는 달을 `view` state 로 옮기고 `shiftMonth(delta)` 를 연결했다.

`Date` 산술 대신 **정수 연산**을 썼다. 달 이동에 `Date` 를 쓰면 1월 31일 + 1개월
= 3월 3일 같은 넘침을 따로 막아야 하는데, 여기서 필요한 건 "몇 월인가" 뿐이다.

`studyDay.ts` 에 `addMonths` 를 추가하지 않았다. 1장이 한 곳에 모으려는 것은
**하루 경계 규칙**이고 그것은 `today`(`getStudyDate`)에만 걸려 있다.

**함께 고친 것** — 오늘 강조 조건을 `day === todayDay` 에서 `key === today` 로
바꿨다. 일(day) 숫자만 비교하고 있어서, 달 이동이 가능해지는 순간 다른 달의 같은
일자까지 전부 오늘처럼 굵게 표시된다.

## 4. 진행 중 — 미래 날짜 생성 시점 이동 (미커밋)

**방향**: 생성 시점을 "선택"이 아니라 "실제 편집"으로 옮긴다.
둘러보기만으로는 아무것도 저장되지 않고, 템플릿 목록은 **미리보기**로만 보여준다.

- `StudyStore.tsx` — `materialize(state, date)` 헬퍼 추가. `ensureDate` 외에
  실제로 데이터를 바꾸는 액션 4개(`addTemplate` / `setTemplateEnabled` /
  `removeTemplate` / `removeTodo`)가 각자 시작할 때 대상 날짜를 만든다.
  이게 없으면 미리보기에서 항목 하나만 건드렸을 때 나머지가 통째로 사라진다.
- `previewFor(date)` 셀렉터 추가 — 저장된 목록이 있으면 그것, 없으면 켜진
  템플릿으로 만든 **미저장** 미리보기. 기록 없는 과거 날짜는 빈 목록.
- `calendar.tsx` — `ensureDate` 는 `selected === today` 일 때만. 목록은
  `previewFor` 로 그리고, 하단 "n / m 완료" 도 화면에 그려지는 목록에서 센다.

17개 케이스로 확인했다. 둘러본 뒤 통계 유지(월 56%, 주 89%), 미래 날짜 편집 시
전체 목록이 깔린 뒤 편집이 적용되는 것, 기록 없는 과거는 빈 목록인 것.

### 기존 오염 데이터 정리

**자동 판정은 불가능하다.** "저장된 목록이 템플릿과 똑같으면 자동 생성된 것"으로
판정하려 했으나 테스트에서 정반대로 동작했다. `addTemplate` 이 전역 템플릿 목록도
함께 바꾸기 때문에, 계획을 세운 날짜가 오히려 "템플릿과 일치" 하게 되어 삭제되고
둘러본 날짜는 남는다.

**확인 후 삭제** 방식을 쓴다. DevTools 콘솔에서:

```js
// ① 확인 (읽기 전용)
(() => {
  const s = JSON.parse(localStorage.getItem("studymate.state.v1"));
  const d = new Date(); d.setHours(d.getHours() - 4);   // 하루 경계 새벽 4시
  const today = `${d.getFullYear()}-${String(d.getMonth()+1).padStart(2,"0")}-${String(d.getDate()).padStart(2,"0")}`;
  console.log("오늘:", today);
  console.table(Object.keys(s.todosByDate).filter(k => k > today).sort()
    .map(k => ({ 날짜: k, 개수: s.todosByDate[k].length, 내용: s.todosByDate[k].map(t => t.title).join(", ") })));
})();
```

```js
// ② 미래 날짜 전부 삭제 (직접 계획한 날짜가 없을 때)
(() => {
  const KEY = "studymate.state.v1";
  const s = JSON.parse(localStorage.getItem(KEY));
  const d = new Date(); d.setHours(d.getHours() - 4);
  const today = `${d.getFullYear()}-${String(d.getMonth()+1).padStart(2,"0")}-${String(d.getDate()).padStart(2,"0")}`;
  const gone = Object.keys(s.todosByDate).filter(k => k > today);
  for (const k of gone) delete s.todosByDate[k];
  localStorage.setItem(KEY, JSON.stringify(s));
  console.log("삭제:", gone.sort().join(", ") || "없음");
  location.reload();
})();
```

지킬 날짜가 있으면 `gone` 을 `["2026-08-22", ...]` 처럼 직접 지정한다.

## 커밋 2 — 수정: 템플릿 enabled 제거, 체크박스를 날짜별 파생값으로

허용된 4개 파일만 수정했다.

- `seed.ts` — `TemplateItem` 에서 `enabled` 제거. `fillFromTemplate` 이 목록의
  모든 항목을 `sortOrder` 오름차순으로 깐다. **`filter` 가 사라져 원본 배열이
  그대로 들어오므로 복사한 뒤 정렬해야 한다** (`[...templates].sort()`).
  이전에는 `.filter()` 결과가 새 배열이라 `.sort()` 가 안전했다.
- `storage.ts` — `STORAGE_KEY` 를 `studymate.state.v2` 로. 마이그레이션 없음.
  `normalizeTemplates` 가 스프레드 대신 `id`/`title`/`sortOrder` 만 뽑는다.
- `StudyStore.tsx` — 액션을 `setTemplateOnDate` 로 개명하고 **`templates` 배열을
  더 이상 수정하지 않게** 했다. 이것이 두 화면이 어긋날 수 없게 만드는 핵심이다.
  삽입 순위 기준을 전체 템플릿으로 바꾸고 셀렉터 `isTemplateOn` 을 추가했다.
- `ListSheet.tsx` — `tpl.enabled` → `isTemplateOn(date, tpl.id)`,
  `aria-label` 을 상태별 두 문구로. 색·여백·레이아웃 무변경.

`index.tsx` / `calendar.tsx` 는 손대지 않았다. 삭제 버튼이 이미 `removeTodo` 를
부르고, 체크가 파생값이 되면서 자동으로 맞는다.

> **주석 표현 조정** — 처음엔 주석에 "enabled 를 제거했다" 라고 적었는데,
> 8절 완료 조건인 `grep -rn "enabled" src/` 가 그 주석 때문에 비지 않았다.
> 검사가 실제로 깨끗해지도록 "on/off 플래그" 로 바꿔 썼다.

## 커밋 3 — 수정: 빈 목록을 존중하고 재시딩하지 않음

### 9번에 대한 정확한 기술

처음 검사에서 9번을 FAIL 로 잡았는데, 리듀서를 직접 호출해 확인한 것이 잘못이었다.
**날짜 가드는 스토어 API 래퍼에 있고 리듀서에는 없다.**

- 실제 UI 경로: `canManage(past)=false` 라 `setTemplateOnDate` / `removeTodo` /
  `addTemplate` / `removeTemplate` 가 dispatch 하지 않는다. `canToggle(past)=false`
  라 `toggleTodo` 도 마찬가지. → 지정된 동작대로 아무 변경이 없다.
- 리듀서를 직접 부르면 과거 목록도 바뀐다. 이번 사이클 이전에도 같았고 지시서
  범위 밖이라 그대로 두었다.
- `ensureDate` 만 가드가 없으나 호출처가 `index.tsx:29` 의 `ensureDate(today)` 와
  `calendar.tsx:94` 의 `if (selected === today)` 뿐이다.
