
#### 4번 — 시작점 유예가 도는 자리

투입한 데이터:

> **10번에 대한 단서** — `current > best` 는 현재 로직에서 자연히 나오지 않는다.
> `current` 가 세는 날들은 모두 기록이 있어 `best` 루프의 대상에도 들어가므로

## 3. 미리 보고할 두 가지

**(1) 트로피 이름이 두 곳에 생긴다 — 어느 쪽을 따를지.**

B-2 가 `rewards.tsx` 안에 `trophyNames = { bronze: "브론즈", ... }` 지역 맵을
두었다. 이번 5절은 트로피 이름을 `브론즈 트로피` 로 고정하고 `TROPHY_NAMES` 를
`rewards.ts` 에 두라고 한다. 그런데 6절 커밋 3은 "트로피 섹션은 지금 그대로
둔다" 고 한다. 둘을 그대로 따르면 **같은 이름이 두 곳에 서로 다른 값으로**
남는다.

- **(가) 권장** — `rewards.tsx` 의 지역 맵을 지우고 `TROPHY_NAMES` 를 쓴다.
  출처가 하나가 된다. 보상 탭 트로피 라벨이 `브론즈` → `브론즈 트로피` 로
  바뀌는데, 5절이 고정 문구로 지정한 값이라 문구 변경 금지에 걸리지 않는다.
  (트로피를 아직 아무도 못 사므로 지금 화면에 보이지도 않는다.)
- (나) 지역 맵을 그대로 둔다. 6절 커밋 3의 문언에는 맞지만 이름이 갈라진다.

**(2) dev 서버가 이미 떠 있다.**

지시서 1절은 dev 서버를 띄우지 말라고 하는데, 직전에 사용자가 따로 지시해서
8080 에 이미 떠 있다. **새로 띄우지 않고, 검증에도 쓰지 않는다.** 7절대로
`rolldown` + Node 로만 검증한다. 내려야 하면 말해 달라.

확인 전까지 코드는 손대지 않았다.

## 4. 진행 확인 — 사용자 지시

(가)로 진행. 사용자 판단: 같은 이름이 두 곳에 다른 값으로 있으면 반드시
어긋난다. "트로피 섹션은 지금 그대로 둔다" 는 **보이는 모양을 바꾸지 말라는
뜻**이었지 이름 출처를 두 개로 유지하라는 뜻이 아니다. 문언과 취지가 갈릴 때
취지를 택한 판단이 맞다.

dev 서버는 내리지 않는다. 지시서의 취지는 "검증을 dev 서버로 때우지 말라"
였고, `rolldown` + Node 로만 검증하는 것이 그 취지에 맞다. 작업 후 사용자가
바로 화면을 봐야 하므로 8080 은 그대로 둔다.

## 7. 사용자 안내 (지시서 10절)

- **보상 탭** — 배지가 **받은 것만** 보인다. 하나도 없으면
  `아직 배지가 없어요. 첫 배지를 받아볼까요?` 가 뜬다. 코인 카드는 없어졌다.
- **`내 컬렉션 모두 보기`** → 시트가 열리고 헤더에 코인, 트로피 3종과 배지
  12종 전부가 조건과 함께 나온다. 못 받은 것은 회색이다.
- **트로피 구매는 아직 안 된다.** 문구만 보이고 눌러도 아무 일이 없는 것이
  정상이다. 구매는 C-2 다.
- **조건 문구가 사용자 말로 읽히는지 봐 주시라.** 어색한 것이 있으면 지금
  고치는 편이 싸다. 문구는 `rewards.ts` 의 `BADGE_REQUIREMENTS` 한 곳에 있다.

## 8. 보고 후 문구 수정 — `b11`

사용자가 `공부의 신` 조건 문구를 고치라고 지시했다.

- 전: `하루 5개 이상 한 날 100일`
- 후: **`하루 5개 이상 완료 100일`**

지시서 5절 표와 달라졌지만, 지시서 10절이 "조건 문구가 어색하면 그 자리에서
고치는 편이 싸다" 고 안내하라 했고 그에 따른 수정이다. **지시서 원문은 고치지
않았다**(0절). 6절 검증의 1번 대조표는 수정 전 시점의 기록이라 그대로 둔다.

문구 출처가 `BADGE_REQUIREMENTS` 한 곳이라 이 한 줄만 고쳤다. 판정 조건
(`BADGES` 의 `daysWith5Plus >= 100`)은 건드리지 않았다 — 표시 문구만 바뀐다.
